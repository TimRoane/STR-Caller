# STR Genotype Caller

A compact Python implementation of an STR genotyping algorithm that separates likely allele signal from expected stutter artifact in repeat-length read-count data.

This repository is intended as a technical portfolio sample. It demonstrates the analytical model and software structure without production-specific workflow integrations, customer data, or proprietary reference datasets.

## Biological problem

Short tandem repeat loci commonly produce a family of nearby read-length peaks rather than a single perfectly clean signal. A major contributor is polymerase slippage during amplification, which can create shorter or longer repeat products around the true allele. This becomes especially challenging for heterozygous loci because a real second allele can overlap the artifact pattern generated by the dominant allele.

The caller therefore does not simply select the two largest peaks. It first estimates expected stutter, removes that expected contribution, and then asks whether remaining signal provides sufficient evidence for a second allele.

## Algorithm overview

For each STR locus, the caller:

1. Combines forward and reverse read counts into repeat-length peaks.
2. Filters to repeat lengths that map to known allele codes.
3. Selects the dominant peak as the primary allele.
4. Models directional stutter from that primary allele.
5. Subtracts the expected stutter contribution from neighboring peaks.
6. Evaluates residual peaks with distance-aware evidence thresholds.
7. Selects a secondary allele only when the residual signal clears both absolute and relative evidence requirements.
8. Removes stutter expected from an accepted secondary allele.
9. Calculates a confidence score based on how much corrected signal is explained by the selected genotype.
10. Returns both the genotype call and a peak-level audit table so the decision can be inspected.

## Stutter model

The model is intentionally asymmetric.

- One-repeat contraction stutter begins at **40%** of the parent peak and decays geometrically at larger negative offsets.
- One-repeat expansion stutter begins at **10%** and decays geometrically at larger positive offsets.
- Non-integral repeat displacements are not treated as stutter in this simplified model.

These values are model parameters, not universal biological constants. They can be replaced with locus-specific or assay-specific calibration values in a production implementation.

## Secondary-allele evidence

A residual peak must satisfy two conditions before being accepted as a second allele:

- a minimum absolute read count; and
- a minimum fraction of the primary-allele signal.

The relative threshold depends on distance from the dominant allele. Peaks close to the primary allele are treated more conservatively because they occur where stutter artifact is strongest. More distant peaks can be accepted with a smaller residual fraction.

This is implemented in `CallerParameters.candidate_fraction()`.

## Quality control

The caller includes explicit no-call states rather than forcing a genotype when the evidence is weak.

Current QC behavior includes:

- `NO_MAPPED_SIGNAL` when no observed repeat peak maps to the allele reference;
- `LOW_DEPTH` when total locus depth is below the configured threshold; and
- `LOW_CONFIDENCE` when the selected genotype does not explain enough of the corrected signal.

The default parameters are collected in the immutable `CallerParameters` dataclass so they can be calibrated and tested independently of the calling code.

## Traceability

`call_locus()` returns two outputs:

1. a locus-level `GenotypeCall`; and
2. a peak-level audit table containing raw reads, corrected reads, allele labels, and whether each peak contributed to the final genotype.

The audit table is intentional. A caller used in a diagnostic or production setting should make it possible to reconstruct why a genotype was selected rather than returning only a final label.

## Input

Read-count TSV:

```text
locus  repeat  forward_reads  reverse_reads
L1     10      620            380
L1      9      250            150
L1     11       80             60
```

Allele-map TSV:

```text
locus  repeat  allele
L1     9       A
L1     10      B
L1     11      C
```

## Command-line usage

```bash
python str_caller.py \
  --reads examples/read_counts.tsv \
  --alleles examples/allele_map.tsv \
  --calls output/calls.tsv \
  --audit output/audit.tsv
```

## Output

The genotype table contains fields such as:

```text
locus  genotype  confidence  status  primary_repeat  secondary_repeat  raw_depth  corrected_depth
```

The audit table contains the per-peak evidence used to make each call:

```text
locus  repeat  allele  raw_reads  corrected_reads  selected
```

## Code structure

The analytical logic is separated from command-line and file I/O concerns.

- `CallerParameters` contains model and QC parameters.
- `stutter_fraction()` defines the directional stutter model.
- `remove_stutter()` subtracts expected parent-allele contribution.
- `collapse_peaks()` creates locus-level repeat peaks.
- `_first_pass()` corrects for primary-allele stutter.
- `_choose_secondary()` evaluates residual second-allele evidence.
- `_second_pass()` removes stutter attributable to the accepted secondary allele.
- `call_locus()` performs one complete locus call.
- `call_panel()` applies the model across loci.
- `_audit_table()` produces traceable peak-level evidence.

This separation makes the analytical core straightforward to test without depending on a workflow engine or cloud environment.

## Validation and tests

A representative test suite should cover at least:

- expected contraction and expansion stutter fractions;
- residual-signal subtraction;
- clear homozygous calls;
- clear heterozygous calls;
- a true secondary allele adjacent to strong stutter;
- low-depth loci;
- low-confidence calls;
- absent allele-map entries;
- loci with no mapped signal; and
- parameter-boundary behavior.

For a production assay, these unit tests would be supplemented with empirical calibration, blinded validation data, reproducibility studies, and documented acceptance criteria.

## Limitations

This portfolio implementation is intentionally compact. It does not claim that one global stutter model is optimal for every STR locus, library preparation, sequencing platform, or sample type.

A production implementation could extend this design with:

- locus-specific stutter parameters;
- motif-length and allele-length effects;
- strand-balance QC;
- empirical noise models;
- replicate support;
- mixture detection;
- learned or probabilistic likelihood models; and
- formally versioned calibration sets.
